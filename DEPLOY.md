# Публикация и управление — пошаговая инструкция

Без серверов, Docker и SSH. Всё работает на бесплатных тарифах:

| Где | Что там | Ваше участие |
|---|---|---|
| **GitHub** | Код, автоматические проверки, публикация, резервные копии базы | Почти никакого — всё запускается само |
| **Cloudflare** | Приложение (Worker), база данных D1, будильник напоминаний | Один раз ввести два секрета |
| **Telegram** | Бот — точка входа и уведомления | Один раз создать бота в @BotFather |

---

## К1. Подготовка аккаунтов

Подробные шаги — в переписке с Claude. Результат К1:

- репозиторий приватный;
- в GitHub (Settings → Secrets and variables → Actions) есть секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`;
- бот создан в @BotFather, его токен сохранён у вас (никому не пересылается).

## К2. Публикация и подключение бота (≈15 минут)

### Шаг 1. Публикация (делает GitHub сам)
После К1 Claude переносит новую версию в основную ветку `main`. GitHub сам проверяет код и публикует приложение на Cloudflare.

✅ Проверка: https://github.com/SFSFfsg/secret-santa-bot/actions — запуски «Тесты» и «Публикация» с зелёными галочками.

❗ Если «Публикация» красная — откройте её и пришлите Claude скриншот красного шага.

### Шаг 2. Найти адрес приложения
1. Откройте https://dash.cloudflare.com → слева **Workers & Pages** (или **Compute → Workers & Pages**).
2. Откройте **secret-santa-nf**.
3. Вверху будет адрес вида `https://secret-santa-nf.ВАШЕ-ИМЯ.workers.dev` — скопируйте его.
4. Откройте в браузере этот адрес, добавив в конце `/setup.html`. Например:
   ```
   https://secret-santa-nf.ВАШЕ-ИМЯ.workers.dev/setup.html
   ```

✅ Откроется страница «Настройка Тайного Санты» с галочками и крестиками — крестики сейчас нормальны.

### Шаг 3. Создать ключ шифрования
Ключ защищает тайну пар: без него никто, включая владельца аккаунта Cloudflare, не прочтёт, кто кому дарит.
1. На странице настройки нажмите **«Создать ключ»** → **«Скопировать ключ»**.
2. Сохраните ключ в менеджер паролей (или в другое надёжное место). **Без него резервную копию пар не восстановить.**

### Шаг 4. Добавить два секрета в Cloudflare
Секреты — это значения, которые знает только приложение: их нельзя прочитать обратно, только заменить.
1. В Cloudflare: **secret-santa-nf** → вкладка **Settings** → раздел **Variables and Secrets** → **+ Add**.
2. **Type:** `Secret`. **Variable name:**
   ```
   BOT_TOKEN
   ```
   **Value:** токен бота от @BotFather → **Deploy** (или **Save**).
3. Ещё раз **+ Add** → **Type:** `Secret` → **Variable name:**
   ```
   ENCRYPTION_KEY
   ```
   **Value:** ключ из шага 3 → **Deploy**.

✅ Проверка: в списке видны `BOT_TOKEN` и `ENCRYPTION_KEY` с пометкой «Secret»; значений не видно — так и должно быть.

### Шаг 5. Подключить бота
1. Вернитесь на страницу `…/setup.html` → **«Проверить ещё раз»**. Должны быть четыре ✅: приложение, база, ключ, бот.
2. Нажмите **«Подключить бота»**.

✅ Появится «Готово! Бот @… подключён».

### Шаг 6. Проверка в Telegram
1. Откройте своего бота → **Старт** (или отправьте `/start`).
2. Придёт фирменная картинка с кнопкой **«🎄 Открыть Тайного Санту»**. Рядом с полем ввода появится кнопка **«Открыть»**.
3. Нажмите — откроется приложение.

## Кто может открывать игры

По умолчанию — любой, кто открыл бота. Чтобы разрешить только организаторам:
1. Узнайте Telegram ID организаторов у бота @userinfobot.
2. Cloudflare → **secret-santa-nf** → **Settings** → **Variables and Secrets** → **+ Add** → **Type:** `Text` → **Variable name:** `ADMIN_IDS` → **Value:** номера через запятую, например `123456789,987654321` → **Deploy**.

## Как обновляется приложение

Изменения в код вносит Claude. После каждого изменения GitHub сам прогоняет тесты и, если всё зелёное, публикует новую версию. Данные в базе при этом не трогаются, участники ничего не замечают.

✅ Проверка: вкладка **Actions** в репозитории — зелёные «Тесты» и «Публикация».

## Резервные копии

- **Автоматически:** каждое воскресенье GitHub делает полную копию базы (запуск «Резервная копия базы»).
- **Вручную:** GitHub → **Actions** → **«Резервная копия базы»** → **Run workflow** → **Run workflow**.
- **Где лежит копия:** откройте запуск → внизу раздел **Artifacts** → `d1-backup`. Хранится 90 дней, видна только вам.
- Пары в копии зашифрованы. Для восстановления нужен ключ `ENCRYPTION_KEY` из вашего менеджера паролей.

**Восстановление.** Процедура восстановления копии во вторую, тестовую базу (с проверкой, что пары читаются) будет добавлена и проверена на пилоте (К4), как согласовано. До этого при любой проблеме с данными напишите Claude — ничего не удаляйте.

## Типовые ошибки

| Что видите | Что делать |
|---|---|
| «Публикация» красная, шаг «Секреты Cloudflare на месте?» | Нет секретов `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` в GitHub — повторите К1, действие 2 |
| «Публикация» красная на шаге «База данных D1» или «Публикация Worker» | У ключа Cloudflare нет прав D1 или Workers — пересоздайте его по К1 (шаблон Edit Cloudflare Workers + D1 Edit) |
| В ошибке упоминается `cron` / «trigger limit» | В аккаунте заняты все 5 бесплатных будильников (например, Property English) — напишите Claude |
| На странице настройки ❌ «Токен бота неверный» | Перевставьте `BOT_TOKEN` (без пробелов). Если токен утёк — в @BotFather `/revoke`, новый токен в Cloudflare |
| ❌ у ключа шифрования | Создайте ключ заново (шаг 3) и перевставьте `ENCRYPTION_KEY`. **Если жеребьёвка уже прошла — не меняйте ключ, напишите Claude** |
| Бот молчит на `/start` | Страница настройки → «Подключить бота» ещё раз |
| Приложение пишет «Не удалось подтвердить вход» | Закройте приложение и откройте снова из бота |
| Человек не получает уведомления | В кабинете организатора у него 📵 — пусть откроет бота и нажмёт «Старт» |
