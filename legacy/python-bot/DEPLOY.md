# Бесплатный запуск: GitHub + бесплатный сервер

Как это устроено:

- **GitHub** (бесплатно) хранит код, при каждом изменении прогоняет тесты и сам выкладывает бота на сервер.
- **Сервер** (бесплатный Oracle Cloud Always Free или любой VPS) держит бота включённым 24/7.

Почему не «только GitHub»: GitHub Actions — это короткие задачи до 6 часов, а не постоянно работающий
сервер. По правилам GitHub держать на нём ботов нельзя, а база с играми стиралась бы после каждого запуска.

---

## Этап 1. Код на GitHub (15 минут)

1. Зарегистрируйтесь на github.com.
2. **New repository** → имя `secret-santa-bot` → обязательно **Private** → Create.
3. Загрузите файлы проекта. Проще всего через программу **GitHub Desktop**:
   File → Clone repository → ваш репозиторий → скопируйте в папку все файлы из архива → Commit → Push.
   - Скрытая папка `.github` тоже должна попасть в репозиторий: без неё не будет тестов и автовыкладки.
     При загрузке через сайт перетаскиванием она часто теряется.
   - Файл `.env` с токеном **никогда** не загружайте на GitHub.
4. Откройте вкладку **Actions**: через минуту «Тесты» должны стать зелёными ✅.

## Этап 2. Бесплатный сервер Oracle Cloud (30 минут)

1. Зарегистрируйтесь на cloud.oracle.com (тариф **Always Free**). Нужна банковская карта для проверки —
   деньги не списываются. Российские карты, как правило, не принимаются.
   - Регион (Home Region) выбирается один раз навсегда — берите ближайший европейский.
2. **Create a VM instance**:
   - Image: **Ubuntu 24.04**;
   - Shape: **VM.Standard.A1.Flex** (1 OCPU, 6 GB) или **VM.Standard.E2.1.Micro** — оба бесплатные;
   - SSH keys: **Generate a key pair** → скачайте **private key** (файл `.key`) и сохраните его.
3. После создания скопируйте **Public IP address** сервера.

> Нет возможности завести Oracle — подойдёт любой VPS за 150–300 ₽ в месяц: 1 ядро, 1 ГБ, Ubuntu.
> Остальные шаги те же.

## Этап 3. Подготовка сервера (15 минут)

Подключитесь к серверу (Windows: PowerShell, macOS: Терминал):

```bash
ssh -i путь/к/ключу.key ubuntu@IP_СЕРВЕРА
```

Выполните по очереди:

```bash
curl -fsSL https://get.docker.com | sudo sh
```

```bash
sudo usermod -aG docker ubuntu
```

```bash
exit
```

Подключитесь заново (команда `ssh` выше) и проверьте, что сервер видит Telegram — должна прийти строка, начинающаяся с `HTTP`:

```bash
curl -sI https://api.telegram.org | head -1
```

Создайте папку и файл настроек:

```bash
mkdir -p ~/secret-santa-bot && nano ~/secret-santa-bot/.env
```

Вставьте и заполните (сохранить: Ctrl+O, Enter, выйти: Ctrl+X):

```
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=ваш_telegram_id
COMPANY_NAME=NF Group
TZ_NAME=Europe/Moscow
REMINDER_HOUR=11
```

## Этап 4. Связать GitHub с сервером (5 минут)

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**. Создайте три секрета:

| Имя | Значение |
|---|---|
| `SERVER_HOST` | IP сервера |
| `SERVER_USER` | `ubuntu` |
| `SERVER_SSH_KEY` | всё содержимое файла приватного ключа `.key`, включая строки `-----BEGIN…` и `-----END…` |

## Этап 5. Запуск (2 минуты)

**Actions → «Выкладка на сервер» → Run workflow.** В конце журнала должна появиться строка
`Бот @…_bot запущен`. Напишите боту `/start` — придёт синяя карточка «Тайный Санта».

## Дальше всё само

- Любое изменение кода на ветке `main` → тесты → если зелёные, бот обновится на сервере сам.
- Бот перезапускается после перезагрузки сервера (`restart: unless-stopped`).
- Журнал бота на сервере:

```bash
cd ~/secret-santa-bot && docker compose logs --tail=50
```

- Резервная копия базы — скачать к себе на компьютер:

```bash
scp -i путь/к/ключу.key ubuntu@IP_СЕРВЕРА:~/secret-santa-bot/data/santa.db .
```

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| «Выкладка» красная, `Нет файла .env` | Этап 3: файл `~/secret-santa-bot/.env` на сервере |
| «Выкладка» красная, ошибка SSH | Секреты из этапа 4: IP, пользователь, ключ целиком |
| Бот молчит | `docker compose logs`: часто это неверный `BOT_TOKEN` |
| `curl` до api.telegram.org не отвечает | Сервер не видит Telegram — нужен сервер в другой стране |
